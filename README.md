# hand-sonar

갤럭시 워치의 스피커와 마이크로 18–21 kHz 초음파 소나를 녹음하고, 폰 정면 카메라로 손 관절 정답을 함께 모으는 안드로이드 앱 두 개입니다. 손 관절 추적 논문 WatchHand([arXiv 2602.21610](https://arxiv.org/abs/2602.21610))를 따라 해 보는 개인 연구용이며, 논문 저자와는 관계가 없습니다.

**연구 현황(실험·처리·학습·분석 방식, 결과, 알아낸 것, 다음 할 일): [docs/research-status.md](docs/research-status.md).** 모은 데이터(관절과 에코 프로파일, 영상·원본 소리 제외)는 [data/](data/README.md)에 있습니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `wear/` | 워치 앱. 18–21 kHz 처프(600 샘플, 48 kHz)를 계속 내면서 마이크를 녹음합니다. 1분 조각 WAV와 기록(`rec.json`), 가속도·자이로·지자기·중력 기록(`sensors-NNN.csv`)을 남기고, 녹음이 멈추면 블루투스로 폰에 넘깁니다. |
| `mobile/` | 폰 앱. 정면 카메라와 MediaPipe Hand Landmarker로 손 관절 21점을 프레임마다 적고(`landmarks.csv`), 같은 프레임을 영상(`video.mp4`)으로 남깁니다. 안내 동작(손가락 굽히기, ASL 숫자, 손목, 자유 동작)을 시간표대로 띄우고(`prompts.csv`), 세션 시작과 끝에 표지음을 냅니다. 폰 센서(`phone_sensors-NNN.csv`)와 세션 정보도 적습니다. 워치가 넘긴 녹음을 받아 두고, 기록 화면에서 zip으로 내보냅니다. |
| `shared/` | 두 앱이 같이 쓰는 순수 Kotlin 코드입니다(처프·표지음 규격, 검출기, 파일 형식, 세션 진행). JVM 시험이 있습니다. |
| `tools/` | PC용 파이썬 도구입니다. 받기(`pull.py`), 녹음 점검(`check_recording.py`), 센서·볼륨·세션 정보 점검(`check_sensors.py`), 표지음으로 시간 맞춤(`align.py`), 에코 프로파일(`profiles.py`), 카메라와 맞춤 검증(`verify_sync.py`), 카메라 프레임↔프로파일 줄 대응표(`pairs.py`), 세션 신호 잣대(`signal_check.py`), 공개 데이터와 나란히 보기(`compare.py`), 손 관절 학습(`joints.py`·`dataset.py`·`train.py`), 학습 결과 영상(`render_video.py`·`render_draw.py`·`hand_seg.py`·`mano.py`), 데이터 묶음 만들기·되돌리기(`export_data.py`·`unpack_data.py`). 실험 스크립트(`experiments/`: 공개 데이터를 우리 형식으로, 공개 모델 전이, 학습 방법 바꾸기)도 있습니다. |
| `data/` | 모은 세션 10개의 손 관절과 에코 프로파일, 그것을 맞추는 기록(영상·원본 소리·센서 제외, [data/README.md](data/README.md)). |

## 두 기기 시간 맞추기

시간 맞추기에는 두 앱의 연결을 쓰지 않습니다. 폰이 세션 시작과 끝에 표지음(21.5→23 kHz, 40 ms)을 내고, PC에서 워치 녹음 안의 표지음을 찾아 두 기기의 시계를 맞춥니다.

## 워치 녹음을 폰으로 넘기기

워치를 adb로 붙일 수 없는 PC에서도 데이터를 모을 수 있게, 워치가 녹음을 블루투스(Wear OS 데이터 레이어)로 짝지은 폰에 넘깁니다. 두 앱이 같은 키로 서명돼 있어야 합니다(아래 "서명").

- 워치는 녹음이 멈추면(정지 이유와 상관없이) 그 녹음을 폰으로 보냅니다. 워치 앱 화면이 보일 때도 아직 못 보낸 녹음을 다시 보냅니다. 새 녹음부터 보냅니다(처음 깔면 쌓인 녹음이 모두 보낼 목록에 드는데, 방금 녹음한 것이 먼저 가게). 녹음하지 않을 때 워치 화면에 보내는 상태가 한 줄 나옵니다.
- 녹음 중에는 보내지 않습니다. 녹음을 시작하면 보내던 파일을 바로 끊고, 폰의 답을 기다리던 중이어도 0.5초 안에 멈춥니다. 녹음이 끝나면 다시 보냅니다.
- 녹음 폴더의 일반 파일을 모두 보냅니다(`part-NNN.wav`, `sensors-NNN.csv`, `rec.json` 등). 쓰다 남은 `.tmp`·받는 중인 `.part`는 보내지 않습니다. 파일 이름은 영문·숫자·`.`·`_`·`-`만 됩니다. 다른 이름이 있으면 그 녹음을 보내지 않고 워치 화면에 알립니다.
- 파일마다 채널 하나로 보냅니다. 폰은 `.part`로 받아 크기와 WAV 머리말을 확인한 뒤 원래 이름으로 바꿉니다. 끊기면 그 파일을 처음부터 다시 보냅니다. 폰이 녹음의 모든 파일을 확인하면 워치는 그 녹음을 "보냄"으로 적습니다. 워치의 녹음은 지우지 않습니다.
- 실패는 녹음마다 셉니다. 실패한 녹음은 1·2·4·8분 쉬며 5번까지 다시 하고, 그동안 다른 녹음은 계속 갑니다. 그 뒤에는 다음 녹음이 멈출 때나 워치 앱을 열 때 다시 합니다. 다시 보내도 같은 거절(WAV 머리말 모양·이름)이면 그 녹음만 막고 워치 화면에 "막힌 녹음 …"을 남깁니다. 폰을 못 찾으면 1분씩 5번 더 찾습니다.
- 폰은 받은 녹음을 `Android/data/com.watchpose.handsonar/files/watch-recordings/<녹음>/`에 워치와 같은 모양(`part-NNN.wav`, `rec.json`)으로 둡니다. 준비 화면과 기록 화면에 받은 녹음 수, 마지막으로 받은 시각, 받는 중 진행률이 나옵니다.
- 폰 앱은 깐 뒤 한 번 열어 둡니다. 강제 중지했거나 삼성 배터리 설정의 "잠자는 앱"·"깊은 잠자는 앱"에 들어 있으면 Play 서비스가 폰의 받기 서비스를 깨우지 못해, 워치에는 "폰이 답하지 않음"만 나옵니다. 그때는 폰 앱을 한 번 열고 잠자는 앱 목록에서 뺍니다.
- 10분 녹음은 소리 약 58 MB에 센서 기록 약 18 MB입니다. 블루투스만으로는 몇 분 넘게 걸릴 수 있습니다.

## 센서·세션 정보 기록

처리·학습은 그대로 두고, 나중에 환경 변수를 가려 볼 수 있게 기록만 더합니다.

- **워치 센서**: 녹음하는 동안 가속도·자이로·지자기·중력을 약 100 Hz로 녹음 폴더의 `sensors-NNN.csv`(1분 조각)에 적습니다. 열은 `t_ns,recv_ns,sensor,x,y,z,accuracy`이고, `t_ns`는 센서 이벤트 시각, `recv_ns`는 앱이 그 이벤트를 받은 때입니다(둘 다 그 기기의 부팅 후 시각 ns, 녹음 시각과 같은 시계). `sensor`는 `acc`(m/s²)·`gyro`(rad/s)·`mag`(µT)·`grav`(m/s²)·`light`(lux, x만)입니다. 이벤트 시각이 부팅 후 시각 기준이라는 것은 안드로이드의 요구일 뿐 기기마다 확인하지 않았기 때문에 받은 시각을 함께 적습니다. 기기가 준 센서(이름·제조사·최대 표본률·분해능 등), 조각·줄 수, 문제는 `rec.json`의 `sensors`에 있습니다. 센서 기록은 소리를 연 뒤에 시작하고 실패해도 녹음을 멈추지 않습니다.
- **워치 "녹음 볼륨"**(그대로·11·13·15): 녹음을 시작할 때 미디어 볼륨을 그 단계로 맞추고 끝나면 되돌립니다. 안드로이드는 미디어 볼륨을 출력 기기마다 따로 두므로, 워치에 블루투스 오디오 같은 외부 출력이 이어져 있으면 볼륨을 바꾸지 않고(그대로 녹음, 화면에 알림) 정지 때 외부 출력이 이어져 있으면 되돌리기를 미룹니다(스피커로 돌아온 뒤 워치 앱을 열 때). 고른 값에 못 맞추면 시작할 때 오류 진동과 화면 한 줄로 알립니다. 녹음 중 앱이 죽었으면 다음에 워치 앱 화면이 보일 때, 그사이 볼륨이 바뀌지 않았을 때만 되돌립니다(바꿨으면 그대로 둡니다). 수집 중에는 워치에 블루투스 오디오를 잇지 않는 편이 낫습니다.
  - `rec.json`의 `volume`: 고른 값(`choice`, 그대로면 null), 맞추려던 값(`target`), 녹음 동안 볼륨(`index`), 원래 볼륨(`original`), 되돌린 뒤(`restored`)와 되돌리지 않은 까닭(`restoreSkipped`), 녹음 볼륨을 걸지 않은 까닭(`skipped`), 시작 때 외부 출력(`outputs`)과 녹음 중 바뀐 때(`outputChanges`), 녹음 중 볼륨이 바뀐 때(`changes`), 앞 녹음이 남긴 볼륨 기록을 다룬 결과(`leftover`). 볼륨 값은 그때 미디어가 나가는 기기의 것입니다.
- **폰 센서**: 세션 동안 가속도·자이로(약 100 Hz, 폰이 그대로였는지)와 주변 밝기(바뀔 때, 카메라 조건)를 세션 폴더의 `phone_sensors-NNN.csv`에, 보고를 `meta.json`의 `sensors`에 적습니다. 접는 폰은 밝기 센서가 두 화면에 하나씩일 수 있고 기본 밝기 센서가 덮개 화면 쪽이면 펼쳐 세운 폰에서는 사용자 반대쪽 밝기를 잽니다. 그래서 쓴 센서는 `sensors.list`, 같은 종류의 다른 센서는 `sensors.others`(주기 0)에 이름으로 남깁니다(워치도 같은 칸이 있습니다).
- **세션 정보**: 폰 준비 화면에서 장소, 자세(앉음·섬), 팔 받침(책상·공중), 줄 조임(헐렁·보통·꽉)을 고르면 다음 실행에도 남고 세션마다 `meta.json`의 `context`에 들어갑니다(고르지 않은 칸은 null).
- **"워치 다시 참"**: 워치를 벗었다 다시 찼으면 준비 화면에서 켭니다. 다음에 보관되는 세션의 `meta.json` `rewear`가 참이 되고 표시는 꺼집니다(취소한 세션이면 켜진 채, 방금 세션을 되돌리면 다시 켜짐). 학습의 세션 나누기는 이 표시 세션부터 다음 표시 전까지를 한 착용으로 묶고, 마지막 착용을 통째로 시험으로 씁니다.
- 새 파일은 다른 파일처럼 폰으로 넘어가고 `pull.py`·내보내기로 PC에 옵니다. 원격 시작에 `--ez sensors false`를 붙이면 그 녹음만 센서 기록을 끕니다(센서 기록이 소리에 주는 영향을 견줄 때).

## 워치 녹음 확인(기울기 연결)

녹음 중인 워치가 중력 값을 0.2초마다 폰으로 보냅니다(데이터 레이어 메시지 `/hand-sonar/tilt`). 워치는 녹음하는 동안만 보내므로, 폰은 이것으로 워치 녹음 중을 봅니다. 준비 화면의 "워치: 녹음 중(기울기 받는 중)"이 이 연결입니다. 폰 마이크로는 워치 처프가 잘 안 들려서, 처프로는 경고하지 않습니다.

- 시작 확인 창은 기울기도 없고 처프도 안 들릴 때만 뜹니다.
- 수집 중 경고는 받던 기울기가 10초 넘게 끊길 때만 뜹니다.
- 요약·기록 화면에는 기울기를 받고 있던 시간 비율("워치 연결")이 나옵니다(`meta.json` `stats.watchLinkRatio`, 처프 비율 `watchHeardRatio`도 그대로 남음).

## 기준 자세(2026-10-31부터 끔)

세션 처음에 팔뚝과 손을 함께 세워 옆면 → 정면으로 2초씩 잡던 단계입니다. 손목 정답의 손 3D를 HaMeR로 바꾼 뒤로는 필요 없어 껐습니다(`SessionController.CALIBRATE`, 켜면 예전처럼 잡습니다).

- **방위**(카메라와 워치가 서로 어느 쪽을 보는지): 기준 자세 없이 손가락·ASL 동작으로 맞춰도 같습니다. 20261031-115740에서 기준 자세로 맞춘 방위가 147.2°, 동작으로 맞춘 방위가 148.9°였고, 손목 정답의 차이는 중앙 0.3°였습니다.
- **0점**: 기준 자세를 손목 각도 0°로 정해 빼던 것도 그만뒀습니다. 앱은 정면에서 깊이 방향을 볼 수 없어, '평행'으로 통과한 자세가 실제로는 평소처럼 약 25° 젖혀져 있었습니다(HaMeR 24°, 같은 세션 숫자 5는 24.7°). 0점을 빼면 세션마다 그만큼 정답이 통째로 밀리는데, 메아리로는 그 차이를 알 수 없습니다. 지금 손목 각도 0°는 손이 워치 축과 일자일 때입니다.
- 켰을 때의 판정: 팔뚝(워치 x축, 위 기울기 연결)과 손(그림 평면 각)이 수직에서 10° 안, 정면은 네 손가락 폄, 2초 유지. "건너뛰기"로 넘길 수 있습니다. 결과는 `prompts.csv` classId −4(옆면)·−3(정면)과 `meta.json` `calibration`에 남고, PC는 그 구간으로 방위만 맞춥니다. 화면 회전은 늘 `meta.json` `camera.displayRotation`에 적습니다.

## 처프 창·모양과 녹음 음원

워치 화면에서 고르고, 다음 녹음에도 남습니다. 녹음마다 `rec.json`의 `tx.window`·`tx.shape`와 `audio`(`source` 실제로 연 음원, `sourceRequested` 고른 음원, `sourceFallback` 바꾼 까닭)에 적힙니다.

- **처프 창**(Tukey · 한 창 · 창 없음): 처음 값은 Tukey 창(양 끝 60샘플 = 처프의 10%씩만 반 코사인으로 줄임)입니다.
  - 한 창은 대역폭을 깎아 직접 경로 봉우리를 두 배로 넓힙니다(반높이 폭 34–85칸, 창 없음·공개 WatchHand 프로파일은 20–21칸). 넓은 봉우리가 손목 가까운 손가락 에코를 덮습니다.
  - 창 없음은 처프 이음새마다 딸깍 소리가 들립니다.
  - Tukey 창은 봉우리 폭을 창 없음 가까이 두고(시뮬레이션 24칸 대 22칸) 들리는 대역 누설을 약 49 dB 줄입니다.
- **처프 모양**(톱니 · 삼각): 처음 값은 톱니(18 → 21 kHz를 되풀이, 공개 WatchHand 데이터와 같음)입니다.
  - 삼각은 앞 반 300샘플에 18 kHz → 21.04 kHz로 오르고 뒤 반 300샘플에 18 kHz로 내립니다. 한 주기가 정수 바퀴(244)라 이음새에서 주파수와 위상이 이어져, 창 없이도 딸깍이 없습니다.
  - 한 줄 전체로 상관하면 움직이는 손가락의 거리 어긋남(도플러)이 오름 반과 내림 반에서 서로 상쇄됩니다(시뮬레이션, 10 cm·0.3 m/s: 톱니 2.6 cm, 삼각 0.2 cm). 대역폭이 같아 봉우리 폭은 그대로입니다.
  - 대신 오름 반과 내림 반이 엇갈려 만나는 성분이 모든 칸에 깔립니다. 이상적인 줄의 봉우리/중앙값이 39.5에서 8.1로 내려가고, 손 거리 칸의 곁봉우리는 0.096에서 0.114로 조금 오릅니다. 그래서 PC 처리는 삼각 녹음에서 직접 경로 문턱을 20배 대신 4배로 씁니다(`profiles.direct_min`).
  - 공개 데이터와 처프가 달라 미리 학습하거나 견주기 어렵고, 톱니 세션과 섞어 학습하기도 어렵습니다.
- **녹음 음원**(UNPROCESSED · 음성 인식 · 자동): 처음 값은 UNPROCESSED입니다. WatchHand는 워치에서 UNPROCESSED로 녹음했습니다(§3.2).
  - 워치8은 UNPROCESSED 지원을 선언하지 않아 "자동"이면 음성 인식(VOICE_RECOGNITION)이 됩니다.
  - UNPROCESSED가 열리지 않으면 음성 인식으로 녹음하고, 시작 때 오류 진동과 화면 한 줄로 알립니다.
  - 원격 시작에 `--es source unprocessed`(또는 `voice_recognition`·`auto`)를 붙이면 그 녹음만 그 음원으로 엽니다.

## 내보내기 (USB 파일 전송만 되는 PC)

폰 기록 화면의 "내보내기"는 보관한 세션과 받은 워치 녹음을 `Download/HandSonar/hand-sonar-<날짜-시각>.zip` 하나로 저장합니다. zip 안은 `phone/sessions/<세션>/…`, `watch/recordings/<녹음>/…`라서 PC의 `hand-sonar-data`에 그대로 풀면 `pull.py`로 받은 것과 같습니다. 받는 중인 `.part`와 쓰다 남은 `.tmp`는 넣지 않습니다.

- "새 것만"은 지난번에 내보낸 뒤 파일 수·크기·시각이 그대로인 폴더를 뺍니다. 기준은 지난번 zip이므로 그 zip을 PC로 옮긴 뒤에만 씁니다(아니면 "전부"). 확인 창에 지난번 zip 이름이 나옵니다.
- 내보내는 동안 앱을 닫지 않습니다. 닫으면 끊겨 처음부터 다시 해야 합니다. 끊겨 남은 숨은 파일은 다음 내보내기 때 지웁니다.

## 빌드

- JDK 17 이상과 Android SDK 36이 필요합니다. `local.properties`에 `sdk.dir`를 적습니다(Android Studio가 만들어 줍니다).
- `./gradlew :wear:assembleDebug :mobile:assembleDebug`
- 폰 앱이 쓰는 MediaPipe 손 모델(`hand_landmarker.task`, 7.8 MB)은 저장소에 없습니다. 첫 빌드 때 구글 공식 주소에서 받아 SHA-256을 확인합니다. 인터넷이 없으면 `-PhandModelUrl=file:///경로/hand_landmarker.task`로 가진 파일을 씁니다.
- 시험: `./gradlew :shared:test`, `python -I -m unittest discover -s tools/tests -t tools`(학습 시험은 torch·timm이 필요합니다)

### 서명

워치 앱과 폰 앱은 applicationId가 같고(`com.watchpose.handsonar`) **같은 키로 서명돼야** 데이터 레이어로 이어집니다. 두 앱의 debug 빌드는 `local.properties`에 `handsonar.keystore`가 있으면 그 키로, 없으면 그 PC의 기본 디버그 키(`~/.android/debug.keystore`)로 서명합니다.

```properties
# 키 파일 경로(상대 경로는 저장소 기준). 윈도 경로는 / 로 쓰거나 \\ 로 씁니다.
handsonar.keystore=D:/keys/hand-sonar-debug.keystore
# 적지 않으면 디버그 키 기본값(androiddebugkey / android)
handsonar.keyAlias=androiddebugkey
handsonar.storePassword=android
handsonar.keyPassword=android
```

- 다른 PC에서 빌드해 지금 깔린 앱을 이어 쓰려면, 그 앱을 서명한 키 파일(처음 빌드한 PC의 `~/.android/debug.keystore`)을 옮겨 그 경로를 적습니다.
- 경로가 적혀 있는데 파일이 없거나, 값을 비워 두거나(`handsonar.keystore=`), 키 경로 없이 별칭·암호만 적으면 빌드가 멈춥니다(조용히 다른 키로 서명하지 않습니다).
- 깔기 전에 `./gradlew :mobile:signingReport :wear:signingReport`로 debug의 SHA-256을 보고, 지금 깔린 앱을 빌드한 PC의 값과 같은지 견준 뒤 `adb install -r`로 덮어 깝니다.
- 키 파일은 저장소에 넣지 않습니다(`.gitignore`가 `*.keystore`·`*.jks`를 막습니다).
- **다른 서명으로 덮어 깔면 설치가 거부됩니다.** 그렇다고 앱을 지우고 다시 깔면 **워치에 쌓인 녹음도 함께 지워집니다**(앱 외부 저장소는 앱과 함께 지워집니다. 폰 앱을 지우면 폰의 세션과 받은 워치 녹음도 지워집니다). 지우기 전에 녹음을 폰이나 PC로 옮겨 두세요.

## PC 처리

파이썬 3.13과 numpy·scipy·matplotlib을 씁니다. 기기에서 받은 파일은 `python -I`로만 읽습니다. 데이터는 저장소 옆 `../hand-sonar-data`에 받고(다른 곳이면 `--data`), 세션마다 결과를 `../hand-sonar-data/processed/<세션>/`에 씁니다. 세션 이름을 주지 않으면 보관된(`kept`) 끝난 세션을 모두 처리합니다.

1. `python -I tools/pull.py` — 폰의 세션과 폰이 받은 워치 녹음, 워치 녹음을 adb로 받습니다. 폰을 먼저 받고(USB라 빠름), 워치에서는 폰에 없거나 크기가 다른 파일만 받습니다. 워치가 없어도 됩니다. 파일마다 받고, `rec.json`·`meta.json`은 그 폴더의 다른 파일을 다 받은 뒤에 받습니다(조각이 빠진 사본이 처리에 들어가지 않게). 기기는 모델(워치 SM-L320, 폰 SM-F971N)로 찾고, `--watch`·`--phone`으로 serial을 줄 수 있습니다. adb를 쓸 수 없는 PC는 폰의 "내보내기" zip을 `hand-sonar-data`에 풉니다.
   - 점검: `python -I tools/check_recording.py <녹음 폴더>`(조각·녹음 시각·재생 끊김), `python -I tools/check_sensors.py <녹음 또는 세션 폴더>`(센서의 실제 표본률·받은 시각 − 이벤트 시각·빈틈과 시계 판정, 녹음 볼륨과 외부 출력·되돌리기, 세션 정보). 센서 CSV는 `hs_io.read_sensors`로 읽고, 맞춤에 쓸 시각은 `SensorLog.ns(종류)`입니다: 기기마다 연속 센서의 받은 시각 − 이벤트 시각 1% 값이 −5–50 ms면 이벤트 시각을 그대로, 아니면 그만큼 옮겨 씁니다(바뀔 때만 내는 밝기는 판정에서 뺍니다).
2. `python -I tools/align.py` — 폰 표지음으로 워치 샘플 번호와 폰 시각을 맞춥니다(`align.json`).
3. `python -I tools/profiles.py` — 공개 데이터(WatchHand)와 같은 처리로 에코 프로파일을 만듭니다(`profiles.npy`, `diff_profiles.npy`, `rows.npz`).
4. `python -I tools/verify_sync.py` — 카메라 관절 속도와 손 거리 소리 세기로 남은 지연을 잽니다(`sync.json`, `sync.png`). 지연이 1프레임(33 ms) 밖이거나 상관 봉우리가 문턱(0.1) 아래면 맞춤을 확인하지 못한 세션으로 적고 끝 코드 1로 끝납니다.
5. `python -I tools/pairs.py` — 카메라 프레임마다 프로파일 줄을 짝짓습니다(`pairs.csv`). 지연이 1프레임 안이고 상관이 문턱 이상인 세션만, 그리고 `sync.json`이 지금의 `align.json`·`rows.npz`·`landmarks.csv`에서 잰 것일 때만 짝짓습니다. 아니면 `pairs.csv`를 쓰지 않고(옛 것은 `pairs.stale.csv`로 바꿈) 끝 코드 1로 끝납니다.
   - 신호 잣대: `python -I tools/signal_check.py [세션 …]` — 학습 없이 녹음 신호를 거칠게 봅니다(`signal.json`).
     - 넷을 잽니다: 정답 관절 속도와 손 자리(칸 301–360) 차분 세기의 로그 상관, 움직임 대비(그 세기의 95% ÷ 중앙), 직접 경로 반높이 폭(처프 창 확인용), 줄 사이 직접 경로 흔들림.
     - 같은 처리로 잰 공개 WatchHand(참가자 9 왼손) 10세션은 상관 0.39–0.70, 대비 4.6–10.9, 폭 21칸입니다. 이 데이터는 같은 처리·학습으로 같은 세션 안에서 손 모양을 따라갔습니다.
     - 2026-10-28 우리 세션(한 창, 음성 인식 음원)은 상관 0.12–0.40, 대비 2.5–3.7이었고 따라가지 못했습니다.
     - 맞춤 문턱에 걸려 `pairs.csv`가 없는 세션도 잽니다(대응은 그 자리에서만 만들고 파일을 쓰지 않습니다).
6. `python -I tools/compare.py <세션>` — 공개 데이터 왼손 표본과 나란히 그린 그림입니다(`compare.png`, 표본 위치는 `--public`).
7. `python -I tools/train.py [--mode session|blocks|time|overfit] --run <이름>` — 대응표까지 만든 세션(표지음 둘, 맞춤 확인)으로 FastViT-T12(timm `fastvit_t12`, 처음부터)를 학습해 손목 기준 손 관절 20점을 회귀하고 평가합니다. 나누기는 `--mode`가 없으면 세션이 둘 이상일 때 `session`(세션 단위: 마지막 착용 — 워치를 다시 찬 뒤 — 의 세션을 통째로, 착용이 하나뿐이면 가장 늦은 세션을 시험에 두고 `--test`·`--val`로 고를 수 있음), 하나일 때 `blocks`(10 s 블록을 학습·검증·시험에 흩음, 같은 착용 안의 낙관적 상한)입니다. `time`은 세션마다 앞 70% 학습·15% 검증·끝 15% 시험(세션 안 낙관적 상한), `overfit`은 모든 프레임으로 학습·평가합니다(외울 수 있는지). 평가는 평균 자세 대비 비가 맨 윗줄이고, 회귀 기울기와 평활한 예측의 σ비(평균 쏠림), 편 손 쪽 투영 치우침(ASL-5, mm), 정답 잡음 바닥을 함께 냅니다. 결과는 `../hand-sonar-data/processed/training/<이름>/`(`dataset.npz`(창 없이 row·목표·라벨·입력 지문, `--save-x`면 창도), `model.pt`, `metrics.json`, `report.png`)에 씁니다. torch(CUDA)와 timm이 필요합니다. 공개 데이터로는 학습하지 않습니다.
   - 학습 증강 `--shift 5 --mask`(논문 §3.6.4): 묶음(연속 32프레임)의 절반에 거리 축 ±5칸(약 1.8 cm, 워치를 찬 위치가 바뀐 것) 무작위 이동을 주고, 그중 80%는 시간 5–15줄·거리 5–10칸 구간을 가립니다. 이동은 창을 칸 295–364로 넓게 만들어 두고 60칸을 잘라 다시 표준화하므로 빈자리가 0이 아닌 실제 이웃 칸입니다. 검증·평가는 증강 없이 가운데 60칸입니다.
   - 공개 데이터(참가자 9 왼손 10세션)의 세션 나누기에서 증강을 켜면 평균 자세 대비 비가 1.07에서 0.87로 내려갔습니다(씨앗값 3개 평균, 2026-10-30).
   - 손목 상태 다중 과제 `--wrist 0.1`: 출력을 63값으로 늘려 뒤 3값이 손목 정답(워치 축으로 적은 손 방향, 아래)을 맞추고, 손실에 0.1배로 더합니다. 카메라 깊이 성분은 0.25배로만 봅니다(MediaPipe 깊이를 믿기 어려워서). 손가락 계기는 그대로이고, 시험 프레임의 손목 각 오차(모델과 학습 평균 방향, 젖힘·꺾임, 그림 평면 성분)가 `metrics.json` `wrist`에 더해집니다.
   - 손목 정답(`tools/wrist.py`, 학습 자료가 부름): 워치 자세는 자이로를 적분하고 중력으로 기울기를 바로잡습니다(지자기 안 씀). 카메라 → 세계는 폰 가속도로 기울기를, 방위는 손가락·ASL 동작에서 손의 새끼 쪽 축을 워치 y축에 맞춥니다(손목을 젖혀도 그 축은 돌지 않음. 기준 자세가 있는 세션은 그 구간의 손 축 셋으로). 0점은 빼지 않아, 각도 0°는 손이 워치 축과 일자일 때입니다. 워치·폰 센서 기록이 없는 세션(공개 데이터 포함)은 손목 정답이 없습니다. `python -I tools/wrist.py`는 세션마다 방위·드리프트·동작별 젖힘·꺾임을 보고합니다. 각도는 워치 기준입니다. 카메라는 손 방향만 재고, 폰 중력·방위 맞춤·워치 자세로 워치 축에 옮깁니다.
   - 손 3D를 HaMeR로(권장, `tools/hamer_keypoints.py`):
     - 왜: 손목 정답의 손등·손바닥 쪽 꺾임은 정면 카메라에서 깊이 방향입니다. 손목 굽히기를 숫자 5와 견주면 MediaPipe 3D는 10세션 중 5개만 바른 방향이었고, 다시점 3D로 학습한 단안 손 복원 모델 HaMeR(arXiv 2312.05251)는 10개 모두 맞혔습니다(그림 평면의 옆 꺾임은 둘이 같음).
     - 결과: 세션 영상에 HaMeR를 돌려 처리 폴더에 `hamer.npz`(프레임마다 3D 관절 21개)를 쓰고, `wrist.py`는 그것이 있으면 씁니다(없으면 MediaPipe 3D).
     - 설치(처음 한 번, 저장소 밖 `../hamer`): `git clone https://github.com/geopavlakos/hamer ../hamer`, 그다음 `python -I tools/hamer_keypoints.py --setup --mano <MANO_RIGHT.pkl>`. 모델 묶음 6.04 GB를 받으면서 체크포인트 2.69 GB와 설정만 꺼내고, MANO 오른손을 chumpy 없는 파일로 바꿔 둡니다.
     - 추가 패키지: `smplx==0.1.28`, `yacs`, `einops`, `pytorch-lightning`, `webdataset`. 렌더러는 쓰지 않습니다.
     - 실행: `python -I tools/hamer_keypoints.py [세션 …]`(GPU, 세션당 약 40초). 영상에 얼굴이 찍혀 있어 PC 안에서만 돌립니다.
   - 줄 단위 정규화 `--row-norm`: 원본 프로파일의 줄(처프 하나, 12.5 ms)마다 600칸 |값| 합으로 나누고 차분을 다시 냅니다. 워치8 녹음은 받은 소리 전체가 줄마다 약 0.3%씩 함께 흔들려(공개 0.13%) 손이 멈춰도 손 자리 칸이 바뀌는데, 이 몫을 없앱니다. 속도–세기 상관은 0.30–0.35에서 0.46–0.50으로 오르고, 세 세션 블록 학습(씨앗값 3개)의 평균 자세 대비 비는 평균 0.964에서 0.910으로 조금 나아졌습니다(씨앗값 사이 흩어짐과 비슷한 크기). 기본은 끔입니다.
   - 손가락 정답 `--gt hamer`: 손가락 목표도 HaMeR 3D로 만듭니다(`hamer.npz`가 있는 세션만, 프레임 거르기와 L은 MediaPipe 그대로). 기본 `mediapipe`는 논문과 같은 정답이라 논문 수치(MPJPE 7.87 mm)와 직접 견줄 수 있습니다.
     - 11세션에서 견주면 HaMeR가 어느 손가락이 굽었는지는 조금 더 잘 가르고(AUC 0.946–0.963 대 0.929–0.960), 굽힘 크기는 1.4–1.8배 크게 읽었습니다. 손가락도 카메라 쪽으로 굽어, MediaPipe가 깊이를 눌러 읽는 것과 맞습니다.
     - 두 정답은 같은 프레임에서 관절당 중앙 13.6 mm 다릅니다. 실행 이름(`--run`이 없을 때)과 `metrics.json` `gt`에 남고, `render_video.py`는 그 실행의 정답으로 그립니다.
8. `python -I tools/render_video.py <학습 결과 폴더> --out <저장소 밖 폴더> [--session 세션] [--frames test|all] [--seg]` — 학습한 모델의 결과를 영상으로 봅니다.
   - 한 화면: 손 영상 위 겹쳐 보기(정답 = 흰 선, 예측 = 파란 띠), 손바닥 틀 3D 두 시점(정답·예측·학습 평균 자세), 동작·MPJPE·역할 꼬리표, 오차 시간 띠(모델과 평균 자세 상수, 커서 = 지금 프레임).
   - 나누기는 그 실행의 `metrics.json`대로 다시 만들고, 기본(`--frames test`)은 시험 프레임만 그립니다(블록 나누기는 시험 블록마다 제목 카드). 예측은 그 세션의 창을 다시 만들어 `model.pt`로 냅니다.
   - `--seg`는 손만 남기고(랜드마크 마스크 + GrabCut) 배경·얼굴을 가립니다. 영상이 없으면(데이터 묶음만 받은 PC 등) 화면 좌표 뼈대로 그립니다(`--no-video`). 공개 데이터 변환은 `--video`로 원본 mp4를 줍니다. `--check N`은 영상 대신 PNG N장입니다.
   - `--mano <MANO_LEFT.pkl>`은 3D 뼈대 대신 정답·예측 관절에 맞춘 MANO 손 메시를 그립니다(프레임마다 맞춤, 평활 없음, 맞춤 잔차 표시). MANO 모델은 https://mano.is.tue.mpg.de 에 등록하고 받으며(비상업 연구용 라이선스) 저장소에 넣지 않습니다.
   - opencv-python·Pillow·imageio-ffmpeg(없으면 PATH의 ffmpeg)와 한글 글꼴(못 찾으면 `--font`)이 필요합니다. 얼굴이 찍힌 영상에서 만들므로 출력은 저장소 밖에만 씁니다.

## 설치와 사용

1. 워치(무선 디버깅)와 폰에 APK를 설치합니다. 두 APK는 같은 키로 서명한 것이어야 합니다(빌드 › 서명).
   - `adb -s <워치> install -r wear/build/outputs/apk/debug/wear-debug.apk`
   - `adb -s <폰> install -r mobile/build/outputs/apk/debug/mobile-debug.apk`
2. 워치 앱에서 녹음을 시작합니다. 미디어 볼륨이 0이면 시작하지 않습니다. "녹음 볼륨"을 고르면 녹음 동안 미디어 볼륨을 그 단계로 맞추고 끝나면 되돌립니다.
3. 폰을 가로로 세우고(폴드는 펼쳐서) 정면 카메라가 손을 보게 둡니다. 표지음은 앱이 낼 때만 미디어 볼륨을 잠깐 올렸다 되돌립니다. 이어폰·블루투스 오디오는 빼 두는 편이 안전합니다. 준비 화면에서 추적할 손(워치를 찬 손)과 세션 정보를 고르고(워치를 다시 찼으면 "워치 다시 참") 시작합니다.
4. 화면 안내대로 손을 움직입니다. 끝나면 요약이 나옵니다(기준 자세 단계는 2026-10-31부터 끔, 위 "기준 자세").
5. 데이터는 각 기기의 `Android/data/com.watchpose.handsonar/files/` 아래에 남습니다(워치 `recordings/`, 폰 `sessions/`와 워치에서 받은 `watch-recordings/`). `pull.py`나 폰의 "내보내기"로 PC에 가져옵니다.

확인한 기기는 갤럭시 워치8과 갤럭시 Z 폴드8뿐입니다. 다른 워치는 스피커가 18–21 kHz를 내고 마이크가 48 kHz로 녹음해야 합니다. 폰 앱은 arm64 기기만 지원합니다.

## 데이터

수집한 영상(얼굴이 찍힘)과 원본 소리(방 안의 말소리가 함께 녹음됨)는 이 저장소에 넣지 않습니다. 대신 손 관절과 에코 프로파일(18–21 kHz만 거른 처리 신호), 그것을 맞추는 기록을 [data/](data/README.md)에 넣었습니다(`tools/export_data.py`가 만들고 `tools/unpack_data.py`로 학습 폴더로 되돌립니다).

공개 WatchHand 데이터셋(Cornell eCommons)으로 학습하려는 경우의 영상–에코 프로파일 시간 맞추기, 검증, 관절 정답 만들기는 [docs/public-watchhand-data.md](docs/public-watchhand-data.md)에 있습니다.
